# Build a Read-Only Streamlit Dashboard with Tailscale Serve

Work in:

```text
jijoece/ai_stock_trading
```

Build a private, read-only Streamlit dashboard that runs on this MacBook and is accessible remotely through **Tailscale Serve**.

The dashboard should show:

* stocks evaluated;
* stocks bought or submitted to simulated paper trading;
* why a stock was bought;
* why another stock was not bought;
* screening, evidence, research, policy, risk, budget, and execution outcomes;
* portfolio and paper-book status;
* research-cycle history;
* provider health;
* scheduler and pause status.

Do not add trading controls, order-placement buttons, approval buttons, pause/resume controls, or scheduler controls.

Do not use Tailscale Funnel.

---

# Execution strategy

This is a large task. Complete it in **four separate Claude Code sessions**.

Each session must execute only one phase:

```text
Phase 1 — Data discovery and view contracts
Phase 2 — Streamlit foundation and decision explorer
Phase 3 — Portfolio, cycles, and system health
Phase 4 — Tailscale Serve, scripts, security, and final validation
```

Do not complete multiple phases in one session.

At the end of each phase:

1. update the handoff file;
2. record files changed;
3. record focused test results;
4. identify the exact next task;
5. stop.

Start the next phase in a fresh Claude Code session.

Do not depend on chat history between sessions.

# Safety boundaries

The dashboard must remain entirely read-only.

Do not:

* place, approve, modify, cancel, or preview broker orders;
* enable external paper execution;
* enable live trading;
* enable scheduled execution;
* alter pause or kill state;
* invoke real Claude Code, Claude Code, Anthropic, Alpaca, SEC, Reddit, Robinhood, or other external services;
* use real credentials;
* add provider fallback;
* expose arbitrary SQL;
* run database migrations from the dashboard;
* expose SQLite database downloads;
* expose local filesystem paths;
* expose credentials, tokens, account numbers, raw prompts, raw model responses, raw subprocess output, or unrestricted exceptions;
* bind Streamlit to `0.0.0.0`;
* configure router port forwarding;
* enable Tailscale Funnel.

All tests must be offline and use temporary SQLite databases and fixtures.

Keep all execution and scheduling defaults disabled.

# Phase 2 — Streamlit foundation and decision explorer

## Objective

Build the application shell and the highest-value decision views.

Read the handoff first. Do not repeat Phase 1 discovery.

## Read-only database helper

Create a read-only connection helper.

Preferred SQLite pattern:

```python
sqlite3.connect(
    f"file:{database_path}?mode=ro",
    uri=True,
)
```

Use:

```text
AI_STOCK_TRADING_DB_PATH
```

as the explicit database-path environment variable unless an existing safe configuration source already exists.

Requirements:

* fail with a friendly sanitized error when missing;
* verify the file exists;
* use `sqlite3.Row`;
* use parameterized queries;
* never call `commit`;
* never create or alter tables;
* never execute migrations;
* do not expose arbitrary query text;
* use short-lived connections or a thread-safe controlled resource;
* do not expose the full path in the UI.
