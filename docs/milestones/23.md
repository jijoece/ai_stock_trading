# Milestone B — Deterministic Strategy-Based Candidate Selection

Start this milestone only after Milestone A is cleanly committed and the external reconciliation design is stable.

Create a separate branch:

```bash
git checkout main
git pull --ff-only
git checkout -b feature/deterministic-strategy-candidate-selection
```

## Why this milestone is worthwhile

The current application uses one combined score:

```text
fundamentals
technicals/momentum
catalysts/risk
Reddit sentiment
```

That ranking can identify generally promising companies, but it cannot clearly explain whether a candidate was selected because of:

```text
mean reversion
momentum breakout
event-driven catalyst
```

Implementing separate deterministic strategy signals is valuable because it enables:

* strategy-specific candidate selection;
* separate backtests;
* independent performance measurement;
* clear entry and invalidation logic;
* comparison of strategy effectiveness;
* reduced LLM usage by analyzing only the best deterministic candidates.

Do not replace the current composite score.

Use strategy signals as a candidate-generation layer before the existing research committee.

Target flow:

```text
verified universe
→ hard liquidity/safety screening
→ deterministic strategy scanners
→ strategy-specific ranking
→ portfolio/risk filters
→ small candidate shortlist
→ bounded evidence acquisition
→ optional AI research committee
→ conservative overlay
→ paper execution
```

# B3 — Momentum Breakout strategy

Implement this first because the current app already has momentum, relative-strength, trend, and price-volume factors.

Use a deterministic strategy such as:

```text
close exceeds prior N-day high
volume ratio exceeds configured threshold
trend filter positive

entry not excessively extended above breakout level
minimum liquidity satisfied
```

Configurable inputs might include:

```yaml
momentum_breakout:
  enabled: true
  breakout_lookback_days: 20
  trend_sma_days: 50
  volume_lookback_days: 20
  minimum_volume_ratio: 1.5
  minimum_relative_strength: 0.0
  maximum_breakout_extension_percent: 3.0
  atr_stop_multiple: 2.0
  maximum_holding_days: 20
```

Do not hard-code these example values without checking existing conventions.

Signal strength should be calculated from deterministic factors such as:

```text
breakout distance
volume confirmation
trend slope
relative strength
distance from moving average
volatility-adjusted extension
```

Fail closed when required bars or volume data are missing.

Do not let a model decide whether a breakout occurred.

# B4 — Mean Reversion strategy

Implement as a separate strategy.

Do not mix its score into momentum-breakout logic because the two strategies can produce contradictory signals.

Possible deterministic entry criteria:

```text
price below short-term moving average by configured threshold
negative z-score over rolling return or price deviation
RSI below configured level
longer-term trend not structurally broken
liquidity sufficient
no major adverse event
```

Possible configuration:

```yaml
mean_reversion:
  enabled: true
  mean_lookback_days: 20
  zscore_entry_threshold: -2.0
  rsi_period: 14
  maximum_entry_rsi: 30
  long_trend_sma_days: 200
  require_price_above_long_trend: true
  atr_stop_multiple: 1.5
  maximum_holding_days: 10
```

The strategy must distinguish:

```text
temporary statistical stretch
structural business deterioration
```

Deterministic safety gates and evidence risk flags must prevent buying merely because a collapsing stock appears statistically cheap.

No averaging down.

Only one initial entry intent per signal.
