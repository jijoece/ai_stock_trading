## A1 — Never initialize financial state while reading exposure

### Current problem

Real mode currently constructs:

```python
PaperLedger(conn)
```

`PaperLedger` initializes missing cash state using its default `$100,000` starting cash.

A portfolio-read operation must never:

* create financial state;
* seed starting cash;
* create a simulated account;
* commit settlement changes;
* mutate any ledger table.

### Required behavior

Replace the real-mode portfolio source with a strictly read-only provider.

The provider must:

```text
require existing book-scoped account state
require an explicit book_id
perform no inserts
perform no updates
perform no settlement
perform no commits
return incomplete when required state does not exist
```

Do not fix this by passing `starting_cash=0`.

Do not instantiate `PaperLedger` on the real-mode exposure path.

### Empty database behavior

When the database has no initialized book/account state:

```text
account_verified = false
account_query_complete = false
positions_query_complete = false
symbol_exposure_complete = false
```

The portfolio read must not create:

```text
paper_cash_state
simulated_positions
book-scoped cash rows
book-scoped position rows
```

## A2 — Read the authoritative book-scoped paper portfolio

### Current problem

The provider currently reads the legacy global simulation tables:

```text
simulated_positions
paper_cash_state
```

External paper fills and isolated paper books use the book-scoped paper-book position and cash repositories.

### Required source

Build portfolio exposure from the same persisted state used by:

```text
paper_books.positions
paper_books.cash_ledger
external-paper fill reconciliation
paper-book risk validation
```

Require an explicit:

```text
book_id
```

The snapshot must include only that book’s:

```text
confirmed position quantities
reserved position quantities when relevant
settled cash
reserved cash
available settled cash
account/book identity
```

Do not combine positions from different books.

Do not use a global local-ledger identity such as:

```text
paper_ledger:local
```

Prefer a bounded identity such as:

```text
paper_book:<book_id>:<sanitized-account-fingerprint>
```

Do not persist raw broker account identifiers.

### Equity calculation

Do not mark account equity complete unless every open position has a valid, fresh market price.

Calculate:

```text
equity =
confirmed cash components
+ sum(position quantity × authoritative market price)
```

Do not use cost basis as current market value.

If any held position lacks a valid mark:

```text
symbol_exposure_complete = false
account_equity may remain unknown
```

Do not represent an incomplete account as zero exposure.

## A4 — Preserve point-in-time semantics

### Current problem

The provider can read current ledger state and assign:

```text
account_as_of = requested cycle as_of
positions_as_of = requested cycle as_of
```

This can make a later fill appear to have existed earlier.

### Required behavior

A current-state provider must use the actual snapshot/retrieval timestamp:

```text
account_as_of = actual read timestamp
positions_as_of = actual read timestamp
```

Do not replace these values with the requested cycle timestamp.

### Current cycles

For a current cycle, accept the snapshot only when:

```text
snapshot timestamp <= evaluation timestamp
snapshot age <= configured freshness threshold
```

### Resume and historical cycles

When the requested cycle `as_of` is earlier than the current account snapshot:

```text
symbol_exposure_complete = false
reason = historical_portfolio_snapshot_unavailable
```

Do not use today’s portfolio for an earlier cycle.

Do not allow a five-minute tolerance to relabel later account state as earlier state.

Historical completeness requires an actual persisted historical snapshot whose timestamp is at or before the cycle `as_of`.

If no such source currently exists, fail closed rather than adding a large historical reconstruction feature.

## B1 — Use an exact stable provider-attempt identity

### Current problem

Reservation identity includes the UTC date.

Unresolved cross-date blocking checks `AMBIGUOUS` rows, but an `IN_FLIGHT` row from the prior date may be ignored.

### Required identity

Persist or derive an exact stable attempt key excluding budget date:

```text
research_run_id
symbol
provider
model
role
attempt_number
```

Recommended:

```text
provider_attempt_key
```

Example canonical content:

```text
research_run_id=<...>
symbol=<...>
provider=<...>
model=<...>
role=<...>
attempt=<...>
```

Hash it if storage length is a concern.

Do not rely on broad string-prefix matching when structured columns are practical.

The UTC budget date remains part of the daily reservation identity, but not the provider-attempt identity.

---

## B2 — Block unresolved `IN_FLIGHT` and `AMBIGUOUS` attempts across dates

Before creating a reservation for an attempt, search across every budget date for the exact provider-attempt key.

Block when any matching row is:

```text
IN_FLIGHT
AMBIGUOUS
```

Required outcomes:

```text
matching IN_FLIGHT
→ TOKEN_ATTEMPT_ALREADY_IN_FLIGHT
→ provider not called
```

```text
matching AMBIGUOUS
→ TOKEN_RESERVATION_RECONCILIATION_REQUIRED
→ provider not called
```

Do not create a new current-date reservation.

Do not assume a new UTC date means a new provider attempt.

---

## B3 — Recover expired claims before reservation creation

Integrate expired-claim recovery into an operational boundary.

Preferred sequence inside the token-budget controller or reservation boundary:

```text
begin atomic budget operation
identify exact matching expired IN_FLIGHT claims
transition expired claim to AMBIGUOUS
check unresolved attempt states
create or reuse reservation only when safe
commit
```

Avoid a separate recovery transaction followed by an unprotected reservation race.

If integrating within `reserve_research_tokens()` would overcomplicate the function, create one focused function that performs:

```text
recover expired matching claim
+
validate unresolved provider attempt
+
reserve current attempt
```

atomically.

### Required behavior

```text
expired IN_FLIGHT
→ AMBIGUOUS
→ no provider retry
→ operator reconciliation required
```

A live, nonexpired `IN_FLIGHT` remains `IN_FLIGHT`.

Do not automatically reclaim or invoke the provider after expiry.

## B6 — Preserve daily token accounting

An expired prior-day claim that becomes `AMBIGUOUS` must remain counted against its original budget date.

Do not move its usage or reservation to the current date.

```text

```

A genuinely new attempt number may proceed only according to existing orchestration retry rules and only when the earlier ambiguous attempt is resolved.
