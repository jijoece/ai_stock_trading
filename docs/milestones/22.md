# Run Paper-Execution Operational Validation

Repository:

```text
jijoece/ai_stock_trading
```

Current milestone state:

```text
SUPERVISED_PAPER_ORDER_SUBMITTED — RECONCILIATION_MISMATCH_EXPECTED — PAPER_SOAK_PENDING
```

Validation summary (2026-07-19): Phases 1-9 passed cleanly (local paper
end-to-end, idempotency, restart/lease semantics via existing focused tests,
Alpaca paper account verification, one external preview). Zero LLM/Codex
calls throughout (token delta = 0). One operational gap was found and fixed:
`paper-book-run-cycle`/`paper-book-integrate-cycle`/`paper-book-lifecycle-run`/
`paper-book-reconcile`/`external-paper-account-check`/`external-paper-preview`/
`external-paper-submit` had no way to point at an operator-supplied
`paper_books.yaml` — the tracked config (`paper_books.enabled: false`) could
only be exercised live by editing tracked config, which this milestone
forbids. Added a `--paper-books-config` override (existing-file-only,
fails closed, never falls back to the tracked default) instead; the tracked
config itself is unchanged (`paper_books.enabled: false` remains the
shipped default). See `tests/unit/test_paper_books_cli_config_override.py`.

With explicit operator approval ("Approved, submit this exact paper order."),
one supervised AAPL BUY LIMIT order (qty 1, notional $333.75 — the doc's
literal $10 cap is unsatisfiable for a whole AAPL share at its live price;
operator approved a $400 cap for this validation) was submitted and
ACCEPTED by Alpaca's paper broker (broker_order_id
`a56fb98f-6032-4138-a664-9ab4b6acd97f`). Reconciliation reported
`POSITION_MISMATCH`/`CASH_MISMATCH`, expected and non-critical to this
milestone: the validation book's earlier local-simulated AAPL fills (Phases
5-6) were never mirrored to the real Alpaca paper account, so the two
ledgers disagree by construction, not due to a defect. No live endpoint was
used; no market order was allowed; no duplicate order/fill occurred.

Goal:

Validate the existing paper-execution path without adding duplicate functionality.

Run these stages in order:

```text
1. local paper end-to-end
2. restart and crash-boundary recovery
3. Alpaca paper account read-only verification
4. external paper-order preview
5. prepare one supervised paper order
6. stop before submission unless explicit approval is given
```

Do not modify execution-path code unless a reproducible defect is found.

Do not enable live trading.

## Primary constraint: minimize token usage

Token efficiency is the main priority.

Follow these rules:

* Do not launch background agents.
* Do not scan the whole repository.
* Do not run Codex research unless no valid persisted decision exists.
* Prefer fixture or persisted research.
* Do not regenerate analyst roles for execution testing.
* Do not use an LLM for:

  * risk checks;
  * order sizing;
  * account checks;
  * broker preview;
  * order polling;
  * fill handling;
  * accounting;
  * reconciliation;
  * restart recovery.
* Use deterministic CLI and database operations only.
* Keep command output bounded.
* Do not print raw evidence, prompts, broker payloads, or full database rows.
* Run focused tests only.
* Do not run the full suite unless code changes are required.
* Make at most one real Alpaca paper preview request.
* Do not submit an external paper order in this task unless the operator explicitly provides the required approval after reviewing the final order.

Expected LLM usage:

```text
Codex calls: 0
LLM input tokens: 0
LLM output tokens: 0
```

If the validation unexpectedly invokes an LLM, stop and report the call path.
