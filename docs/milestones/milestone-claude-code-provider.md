# Production Claude Code Research Provider and Scheduled Shadow Research

Work directly in the current `ai_stock_trading` repository.

Implement a production-ready `ClaudeCodeResearchProvider` that invokes the locally installed Claude Code binary as a locked-down non-interactive subprocess authenticated with a Claude subscription OAuth token.

The intended production flow is:

```text
launchd
→ project launch wrapper
→ run-due-shadow-cycle
→ existing shadow scheduler
→ ClaudeCodeResearchProvider
→ /opt/homebrew/bin/claude -p
→ schema-conforming structured_output
→ existing local schema, claim, provenance, and safety validation
→ existing persistence, usage, budget, health, pause, and readiness systems
```

This is an implementation task. Inspect the current repository before modifying it, implement the changes directly, add comprehensive offline tests, and produce an implementation report.

Do not merely return recommendations or a hypothetical patch.

# Critical authentication constraint

This provider must authenticate through:

```text
CLAUDE_CODE_OAUTH_TOKEN
```

generated by:

```bash
unset ANTHROPIC_API_KEY ANTHROPIC_AUTH_TOKEN
claude setup-token
```

Do not use Claude Code `--bare` mode.

Claude Code subscription OAuth tokens are not read in bare mode. Use `--safe-mode` plus explicit disabling of all tools, MCP servers, customizations, and session persistence.

The provider must never silently fall back to:

```text
ANTHROPIC_API_KEY
ANTHROPIC_AUTH_TOKEN
Anthropic direct API
deterministic provider
another model provider
interactive Claude Code credentials
```

A provider or authentication failure must remain a provider failure.

# Part 2 — Use a locked-down Claude Code command

Construct the command as an argument list. Never use:

```text
shell=True
bash -c
zsh -c
string interpolation into a shell command
```

The production command should be equivalent to:

```bash
/opt/homebrew/bin/claude \
  -p \
  --safe-mode \
  --tools "" \
  --disallowedTools "mcp__*" \
  --strict-mcp-config \
  --disable-slash-commands \
  --permission-mode dontAsk \
  --no-session-persistence \
  --no-chrome \
  --max-turns 1 \
  --model sonnet \
  --output-format json \
  --json-schema '<schema>' \
  --max-budget-usd '<configured-limit>'
```

Use the precise flag spelling accepted by the installed supported version.

Do not use:

```text
--bare
--continue
--resume
--session-id
--allowedTools
--add-dir
--mcp-config
--plugin-dir
--plugin-url
--chrome
--dangerously-skip-permissions
```

Defense in depth:

* `--safe-mode` disables user/project customizations;
* `--tools ""` removes built-in tools;
* `--disallowedTools "mcp__*"` denies MCP tools;
* `--strict-mcp-config` prevents inherited MCP configuration;
* `--disable-slash-commands` disables commands and skills;
* `--permission-mode dontAsk` prevents unattended permission prompts;
* `--no-session-persistence` prevents disk-persisted sessions;
* `--max-turns 1` prevents agent loops;
* `--no-chrome` prevents browser integration.

Do not log the complete command because the JSON Schema may be large. Log only safe static properties such as:

```text
provider
configured model alias
binary version
timeout
maximum turns
schema byte count
prompt byte count
```

# Part 6 — Implement bounded subprocess I/O

Do not use an implementation that buffers unlimited stdout or stderr.

Use `subprocess.Popen` with:

```python
start_new_session=True
```

or the correct macOS equivalent so the provider owns a process group.

Implement concurrent draining of stdout and stderr with hard limits:

```text
maximum_stdout_bytes
maximum_stderr_bytes
```

If either limit is exceeded:

```text
terminate process group
→ wait bounded grace period
→ SIGKILL process group if still alive
→ reap child
→ join reader threads
→ raise typed provider error
```

On request timeout:

```text
SIGTERM process group
→ bounded wait
→ SIGKILL process group
→ wait/reap
→ close pipes
→ join threads
→ raise ProviderTimeoutError
```

The timeout must apply to the entire invocation, including startup and output draining.

Never leave:

* child processes;
* process-group descendants;
* pump threads;
* open pipes;
* zombie processes.

Handle `BaseException` during setup and communication by cleaning up the process group before re-raising.

Use monotonic time for latency and timeout calculations.
