# PR A — External Paper Account Safety

Create:

```bash
git checkout -b fix/external-paper-account-safety
```

## A1 — Make the daily limit account-wide

Current issue:

The `$150` daily external-paper notional limit is calculated separately for each local book.

The same Alpaca paper account can therefore potentially submit up to the cap through multiple books.

Required behavior:

```text
daily cap scope = verified broker account fingerprint + UTC trading date
```

The cap must aggregate submissions from every book associated with that account.

Do not scope the limit only by:

```text
book_id
```

Use the existing sanitized broker-account fingerprint.

Do not persist raw account IDs.

## A2 — Make daily-notional enforcement atomic

A read-then-submit check is insufficient because two books or processes can race.

Implement an atomic account/day reservation.

Prefer reusing an existing budget, lease, reservation, or transaction abstraction if one already exists.

Otherwise create the minimum persisted structure containing:

```text
account_fingerprint
UTC date
client_order_id
book_id
reserved_notional
state
created_at
updated_at
```

Possible states:

```text
RESERVED
SUBMITTED
RELEASED
RECONCILIATION_REQUIRED
```

Required flow:

```text
BEGIN IMMEDIATE
→ calculate submitted + reserved account-wide notional
→ reject if new total exceeds cap
→ create idempotent reservation
→ COMMIT
→ call broker
→ settle reservation to SUBMITTED
```

If broker submission fails before acceptance:

```text
release reservation
```

If acceptance is ambiguous:

```text
retain reservation
mark RECONCILIATION_REQUIRED
do not permit blind retry
```

A duplicate submission using the same client-order ID must reuse the original reservation.

## A3 — Capture reconciliation baseline before submission

Current issue:

The system automatically captures its baseline during first reconciliation. That first reconciliation may happen after an order filled or broker state changed.

Required behavior:

* baseline creation must be an explicit activation/preflight operation;
* baseline must exist before the first external submission for a book/account relationship;
* submission must fail closed when the baseline is missing;
* reconciliation must never silently create a baseline.

Baseline creation must require:

```text
verified paper account
matching account fingerprint
known local state
known broker state
no ambiguous external submission
```

If an external order, broker fill, or submitted event already exists and no baseline exists:

```text
do not create a normal baseline
return BASELINE_REQUIRES_OPERATOR_REVIEW
```

On every later reconciliation:

```text
stored account fingerprint == currently verified account fingerprint
```

Otherwise fail with:

```text
ACCOUNT_FINGERPRINT_MISMATCH
```

## A4 — Tests

Add focused tests for:

```text
$100 submitted from BASELINE plus $51 from ENHANCED is rejected
different broker-account fingerprints maintain independent caps
two concurrent books cannot both reserve past the account cap
duplicate client-order ID does not reserve twice
broker rejection releases the reservation
ambiguous submission keeps the reservation
reconciliation is required before retrying ambiguity
submission without an activation baseline fails closed
reconciliation does not auto-create a missing baseline
baseline cannot be created after external activity without operator review
baseline account fingerprint mismatch fails closed
```

Use only scripted broker adapters.

## A5 — Validation

Run the narrow external-paper tests first.

Run full credential-free tests once after focused tests pass.

```

```

# PR B — Strategy Signal Correctness

After PR A is complete, return to current `main` and create:

## B1 — Use actual source timestamps

Current issue:

The strategies store evaluation time as `data_as_of`.

Required behavior:

For bar-based strategies:

```text
data_as_of = latest input bar.available_at used by the signal
```

For event-catalyst signals:

```text
data_as_of = latest availability timestamp among:
- selected event published timestamp
- relevant event effective timestamp when already effective
- latest confirming bar available_at
```

Do not use `context.now` as a substitute for source-data time.

Validate:

```text
bar.available_at <= context.now
event.published_timestamp <= context.now
event timestamp/effective timestamp cannot introduce future information
```

A future-available input must produce:

```text
INCOMPLETE
```

or:

```text
STALE
```

with a machine-readable reason.

`signal_timestamp` remains the evaluation time.

## B2 — Fix shortlist freshness ordering

When strength and data quality tie:

```text
newer data_as_of ranks before older data_as_of
```

Add a regression test using two otherwise identical signals.

## B3 — Fix event price confirmation

Current issue:

The event strategy uses absolute price movement and can accept a negative response to a positive event.

Calculate signed return:

```text
signed_response_percent =
    (latest_close - pre_event_reference_close)
    / pre_event_reference_close
    * 100
```

Add a validated configuration field:

```text
minimum_positive_response_percent
```

Eligibility must require:

```text
signed_response_percent >= minimum_positive_response_percent
```

Keep maximum-gap/extension protection as a separate upper bound.

Tests:

```text
positive event + negative response = NOT_ELIGIBLE
positive event + insufficient response = NOT_ELIGIBLE
positive event + confirmed positive response = ELIGIBLE
positive event + excessive positive gap = NOT_ELIGIBLE
```

## B4 — Give event-catalyst signals a deterministic stop

Current issue:

Eligible event-catalyst signals have no invalidation price or initial stop and cannot pass the execution boundary.

Add event-catalyst configuration:

```text
atr_period
atr_stop_multiple
```

Calculate a deterministic positive stop.

For an eligible event signal:

```text
initial_stop_reference is not None
invalidation_price is not None
initial_stop_reference > 0
initial_stop_reference < entry_reference
```

If ATR is unavailable or the resulting stop is invalid:

```text
INCOMPLETE
```

Do not fabricate a stop.

## B5 — Fix mean-reversion target

Current issue:

Eligibility requires the current price to be above the long-term SMA, but the target is set to that long-term SMA. The target is therefore below entry.

Calculate and persist the short-term mean corresponding to:

```text
mean_lookback_days
```

Use that as the mean-reversion target only when:

```text
target_reference > entry_reference
```

If the short-term mean is not above entry, either:

* produce `NOT_ELIGIBLE`; or
* leave the target absent and fail execution-boundary readiness.

Prefer failing closed rather than creating a long trade with a target below entry.

Retain the long-term SMA only as a structural trend gate.

## B6 — Strengthen eligible-signal invariants

For every `ELIGIBLE` long strategy signal, require:

```text
data_as_of present and timezone-aware
entry_reference > 0
limit_reference > 0
initial_stop_reference > 0
invalidation_price > 0
stop < entry
expected_holding_period > 0
configuration_hash present
reason_codes present
```

`target_reference` may be optional, but when present:

```text
target_reference > entry_reference
```

Noneligible signals may omit execution fields.

## B7 — Derive one canonical strategy signal ID

Current signal IDs omit important decision inputs.

Create one shared canonical derivation function based on immutable fields:

```text

signal_timestamp

```

Use sorted canonical serialization.

Use the same ID in:

```text

```

Do not maintain two different signal-ID implementations.

## B8 — Tests and validation

Add tests for:

## C1 — Include signals in backtest identity

Current issue:

The shared backtest run ID depends only on backtest configuration. Different strategy signal sets can collide.

Create a deterministic signal-set hash from sorted entry signals:

```text
signal_id
symbol
generated_after_session
limit price
quantity hint
strategy stop
strategy target
strategy holding period
```

Backtest identity must include:

```text
configuration hash
signal-set hash
backtest code version
```

Distinct signal sets must generate distinct run IDs.

Identical configuration and identical signals must remain idempotent.

Do not use `INSERT OR IGNORE` to hide conflicting content under one run ID.

If an existing run ID is found with a different input hash:

```text
fail closed
```

## C2 — Reject mixed strategy definitions

One strategy backtest must not combine signals from different:

```text
strategy versions
configuration hashes
```

Fail closed if eligible signals for one requested strategy contain more than one version or configuration hash.

Persist the strategy ID, strategy version, strategy config hash, and signal-set hash with the backtest result if the current schema supports additive metadata.

Use an additive migration only when needed.

## C3 — Honor strategy-specific exits

Extend the shared `EntrySignal` contract backward-compatibly with optional:

```text
initial_stop_reference
target_reference
maximum_holding_sessions
strategy_signal_id
```

Existing nonstrategy backtest callers may continue using global configuration defaults.

For strategy backtests:

```text
use signal stop when supplied
use signal target when supplied
use signal holding period when supplied
```

Do not silently replace strategy-specific values with global defaults.

Validate:

```text
stop < fill price
target > fill price when target exists
holding period > 0
```

Invalid strategy execution values must reject the signal rather than alter them.

## C4 — Correct strategy metrics

Include BUY fees in round-trip realized P/L and return calculations.

Cost basis should account for:

```text
entry notional
entry fee
```

Ensure SELL fees remain included exactly once.

Track open lots through the end of the test.

Exposure must include both:

```text
completed trades
positions still open at the end date
```

Rename or correct time-to-fill:

* calculate actual market sessions, not calendar days; or
* rename the field to `time_to_fill_calendar_days`.

Prefer true session counting using the backtest session index.

Ensure profit-factor representation is serializable:

* avoid nonfinite JSON numbers;
* use a documented nullable or bounded representation when there are no losses.

Add explicit metric definitions to the strategy documentation.

Tests:

```text
entry and exit fees both reduce P/L
partial exits allocate fees correctly
open end-of-test position contributes to exposure
weekend gap counts as one market session, not three days
all-winning result serializes safely
strategy stop is used instead of global stop
strategy holding period is used instead of global holding period
different signal sets get different run IDs
identical signal sets replay idempotently
mixed strategy configuration hashes fail closed
```

## C5 — Make token budgets enforceable

Current issue:

The research budget helper checks only whether previously spent tokens are below the limit. It can approve a request that will exceed the limit, and its state is not persistent.

First inspect and reuse any existing persisted provider, shadow, or daily-budget subsystem.

Do not build a duplicate budget system if one already exists.

Before a fresh research cycle, calculate a conservative reservation:

```text
estimated input tokens
maximum output tokens
maximum reasoning tokens or configured cycle allowance
```

Enforce atomically:

```text
spent
+ active reservations
+ requested reservation
<= daily token cap
```

Persist reservations using a stable key such as:

```text
research run ID
symbol
provider
model
UTC date
```

States:

```text
RESERVED
SETTLED
RELEASED
AMBIGUOUS
```

Rules:

* reused research consumes no fresh reservation;
* duplicate invocation reuses the same reservation;
* successful calls settle to actual usage;
* unused reserved capacity is released;
* failed-before-call attempts release;
* ambiguous provider outcomes remain reserved until reconciled;
* concurrent processes cannot reserve over the cap;
* process restart preserves the budget state.

Do not silently switch models when the budget is exhausted.

## C6 — Filter symbol concentration before research

The current selector checks only whether total portfolio exposure is below 100%.

Replace that misleading gate with either:

1. a real symbol-level pre-research filter; or
2. remove it and clearly defer concentration to the risk engine.

Because token use is the priority, prefer a real deterministic pre-filter using:

```text
current symbol exposure
estimated minimum candidate allocation
configured ticker allocation cap
```

A symbol that cannot receive any allowed allocation should not consume research tokens.

This pre-filter is advisory for research selection only. Final risk validation remains authoritative.

Run focused backtest and budget tests.
