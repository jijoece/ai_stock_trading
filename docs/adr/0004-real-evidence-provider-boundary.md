# ADR 0004: Real evidence providers plug into the existing Milestone 5 evidence contracts; the scheduled cycle is a loop over existing services, not a new authority

**Status:** Accepted
**Date:** 2026-07-12 (Milestone 6)

## Context

Milestone 5 built an evidence-backed Claude research layer, but every evidence provider was fixture-backed (`research/fixtures.py`, four hardcoded symbols). `docs/milestones/milestone-6.md` asks for real, point-in-time-aware evidence acquisition (SEC filings/company facts, market data, fundamentals, news, sentiment, portfolio context) and a repeatable scheduled-cycle service that compares a deterministic baseline against a Claude-enhanced arm, while explicitly preserving every Milestone 1-5 control: screening, scoring, risk sizing, recommendation freezing, paper execution, ledger accounting, broker reconciliation, and performance evaluation all remain deterministic application code, never Claude, never a provider.

Repository inspection before writing any code surfaced two load-bearing facts that shaped this design:

* `research/evidence.py` already defines the exact Protocol shape a real provider needs to satisfy — `FundamentalsEvidenceProvider` / `MarketEvidenceProvider` / `NewsEvidenceProvider` / `SentimentEvidenceProvider` / `FilingEvidenceProvider` (`fetch(symbol, as_of) -> EvidenceBundle`) and `PortfolioContextProvider` (`fetch(symbol, as_of) -> Mapping | None`). `research/fixtures.py`'s fixture classes are the existing reference implementation. `build_evidence_snapshot` requires **zero changes** to accept a real provider.
* `evaluation/price_provider.py::PriceProvider` (`get_close(symbol, as_of: date) -> PricePoint | None`) is the existing plug point for forward-performance evaluation, separate from the evidence layer's `MarketEvidenceProvider`.
* Milestone 4's `.env.example` documents an existing, load-bearing invariant: `ALPACA_API_KEY`/`ALPACA_API_SECRET` are read *exclusively* by the isolated `paper_runtime` process — "the main trading-desk process never reads these."

## Decision 1: Real providers are a new package underneath the existing evidence Protocols, not a new Protocol layer

`src/trading_research/evidence_providers/` holds raw HTTP clients (`sec_provider.py`, `market_data_provider.py`), normalization (`fundamentals.py`), and thin adapter classes (`evidence_adapters.py`) that convert raw responses into `SourceRecord`/`EvidenceItem` objects and satisfy the *existing* Milestone 5 Protocols exactly. `research/evidence.py`, `research/orchestration.py`, `research/overlay.py`, and every other Milestone 5 module are unmodified except `research/evidence.py`'s own docstring. This is the smallest safe extension point: it is structurally impossible for a real provider to change how a snapshot is built, hashed, or validated, because that code never changed.

## Decision 2: A single real Alpaca market-data client serves both evidence-building and forward evaluation

`evidence_providers/market_data_provider.py::AlpacaMarketDataClient` implements both the raw `MarketDataProvider`-shaped methods (`get_quote`, `get_price_history`) *and* `evaluation/price_provider.py::PriceProvider.get_close` — one real provider, not two overlapping ones, per the milestone's explicit "avoid adding several overlapping market-data providers" guidance. `get_close` never substitutes a live quote for a missing historical close; it calls the same `get_price_history` path and returns `None` when the requested date has no bar.

## Decision 3: Real market-data credentials are deliberately distinct from the Milestone 4 paper-broker credential pair

Milestone 4 established `ALPACA_API_KEY`/`ALPACA_API_SECRET` as read exclusively by the isolated `paper_runtime` process. Rather than silently break that documented boundary by having the main process read the same two variables for market data, `config.py::Config` gained `alpaca_market_data_api_key`/`alpaca_market_data_api_secret`, sourced from the distinct `ALPACA_MARKET_DATA_API_KEY`/`ALPACA_MARKET_DATA_API_SECRET` environment variables (`.env.example`). An operator may set these to the same real key pair Alpaca happens to accept for both purposes, but the code-level invariant — "the main process never reads `ALPACA_API_KEY`/`ALPACA_API_SECRET`" — remains literally true. The main process still never imports LumiBot or alpaca-py; `AlpacaMarketDataClient` speaks plain HTTPS via `httpx`.

## Decision 4: An unconfigured optional provider is excluded from a snapshot's provider list, not included-and-permanently-missing

`research/evidence_validation.py::validate_snapshot_preconditions` (Milestone 5, unchanged) treats *any* non-empty `EvidenceSnapshot.missing_data_reasons` as "missing required evidence" for the preflight check — it does not distinguish "an optional provider that was never configured" from "a required provider that failed." Given news and sentiment are ENVIRONMENTALLY_PENDING in this milestone (no API key; no Reddit credentials), `research/scheduled_cycle.py::EvidenceProviderRegistry.news`/`.sentiment` are `None` when unconfigured, and `build_real_evidence_snapshot` excludes a `None` provider from the snapshot's provider list entirely, rather than querying it only to receive a permanent "not configured" missing-data entry that would degrade every real snapshot's outcome classification. This mirrors Milestone 5's own precedent of scoping the analyst role set down to what has real evidence behind it (`docs/milestones/milestone5-evidence-backed-claude-research.md`: "begin with a smaller role set").

## Decision 5: The scheduled cycle is a loop over unmodified Milestone 1-5 services, not a new authority

`research/scheduled_cycle.py::run_scheduled_research_cycle` calls, per symbol, in order: `services/analyze_candidate.py::analyze_candidate` (unchanged — the baseline arm), `research/evidence.py::build_evidence_snapshot` (unchanged, fed real providers), `research/orchestration.py::analyze_with_research_committee` (unchanged), `research/overlay.py::apply_research_overlay` (unchanged), `research/recommendation_overlay.py::apply_overlay_to_recommendation` (unchanged), and `research/experiment.py::build_experiment_assignments` (unchanged). No new code path constructs a recommendation, computes a share quantity, or mutates ledger/broker state — this module only sequences existing calls and persists cycle-level bookkeeping (`storage/research_cycle_schema.py`, a new but structurally identical table pair to `research_schema.py`'s existing pattern).

## Decision 6: `SHADOW_ENHANCED` is the only default-supported policy that submits anything, and it never submits the enhanced arm

`research/experiment_policy.py` recognizes five policy names from the milestone document but only fully supports `OBSERVE_ONLY`, `BASELINE_ONLY`, and `SHADOW_ENHANCED` — `ENHANCED_ONLY` and `BOTH_SEPARATE_PAPER_BOOKS` are recognized (so config can name them) but raise `UnsupportedExperimentPolicyError` immediately, because they require separate paper-portfolio namespaces this milestone does not implement (the milestone document's own guidance: "implement separate logical paper portfolios or allocation namespaces first"). `may_submit_enhanced()` returns `False` unconditionally for every currently supported policy — there is no code path anywhere that submits an enhanced-arm recommendation to paper execution.

## Decision 7: Real evidence for the deterministic baseline arm honestly inherits the screener's fail-closed design — it is not forced to pass

`research/scheduled_cycle.py::build_real_candidate_input` maps real provider output into the existing typed `CandidateInput` (`price`, `avg_daily_dollar_volume`, `market_cap` from Alpaca+SEC; `revenue_growth_yoy`/`gross_margin`/`operating_margin`/`cash`/`debt`/`shares_outstanding` from SEC company facts). Corporate-status fields this milestone's minimum provider set does not source (`operating_history_years`, `bankruptcy_or_distress`, `going_concern_warning`, `shell_company_flag`) are left `None`. `analysis/screener.py::screen_candidate` (Milestone 2, unchanged) already hard-fails a gate when its critical input is unknown — "a candidate never passes a gate merely because data is unavailable." This mapper does not fabricate a favorable default to force a `buy_candidate` outcome; real-symbol baseline results legitimately land on `screened_out` or `analysis_incomplete` with this minimum provider set, which is documented, not hidden.

## Decision 8: Provider request/response persistence is one append-only table, not the milestone document's illustrative seven

`storage/evidence_provider_schema.py::evidence_provider_requests` merges the milestone document's suggested "requests" and "responses" tables into one row per HTTP attempt — mirroring `research_schema.py::research_attempts`'s own one-row-per-attempt convention. Raw payloads are only persisted when `licensing_classification == PUBLIC_DOMAIN` (SEC EDGAR only) and capped at `MAX_RAW_PAYLOAD_BYTES`; Alpaca market data is `ACCOUNT_LINKED` and never has its raw payload persisted, only normalized `SourceRecord`/`EvidenceItem` data (which already carries a `content_hash` and full provenance) and request-level telemetry (status, latency, cache status, retry count).

## Consequences

* A real provider failure (SEC unavailable, Alpaca unavailable, unconfigured news/sentiment) can only ever produce a `missing_data_reasons` entry or an `EvidenceSnapshot` outcome of `INCOMPLETE_REQUIRED_DATA`/`PROVIDER_UNAVAILABLE`/`POINT_IN_TIME_UNSAFE` (`evidence_providers/normalization.py::classify_snapshot_outcome`) — it cannot silently fall back to fixture data or fabricate a value, and it cannot corrupt the deterministic baseline, which is built and persisted by unmodified Milestone 2 code regardless of the research arm's outcome.
* The known, accepted limitation this ADR records: with only SEC + Alpaca configured (the minimum provider set proven real in this milestone), most real-symbol scheduled cycles will legitimately produce `screened_out`/`analysis_incomplete` baselines rather than `buy_candidate` — see Decision 7. A future milestone that wants real `buy_candidate` outcomes needs a real corporate-status/going-concern data source, not a change to this milestone's fail-closed mapping.
* News and Reddit sentiment real integration remain ENVIRONMENTALLY_PENDING, not because the code path is missing (`evidence_providers/news_provider.py`, `sentiment_provider.py` both exist and are tested) but because no API key/Reddit credential is present in this environment — see `docs/milestones/milestone6-real-evidence-continuous-evaluation.md` "Known limitations."
