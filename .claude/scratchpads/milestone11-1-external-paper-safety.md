## Order-scope locking
- Added `paper_external_order_leases` table (schema added earlier alongside Part 3) + `acquire/load/release_external_order_lease` repo functions: atomic conditional UPSERT (only claims if not ACTIVE or already expired), TTL 30s, wrong-owner release is a no-op.
- Added `_order_lease` context manager in external_broker.py; wraps preview/submit/retry/cancel bodies (lease acquired before reading/transitioning current state; released in `finally`). Reconciliation is split into a public `reconcile_external_paper_order` (resolves client_order_id, acquires lease) and an internal `_reconcile_locked` (assumes lease held) — submit/retry call `_reconcile_locked` directly after their own post-submission reconciliation to avoid self-deadlock on the same lease.
- Failure to acquire raises `ORDER_LEASE_HELD` immediately (no waiting) — a concurrent duplicate submit therefore performs zero runtime calls.
- Tests: concurrent submit blocked by a held lease performs no runtime mutation; stale (expired) lease recovers for a new caller; wrong owner cannot release a lease. 20/20 in test_external_paper_broker.py.
## Cash reservations
- Root cause: `_release_terminal_buy_reservation` released the FULL original notional the instant broker state hit any terminal value, including FILLED with zero/delayed local fills, and never accounted for partial fills before releasing on cancel.
- Added `cash_ledger.remaining_buy_reservation`, `release_settled_buy_reservation` (per-fill, idempotent by fill_id, clamped to remaining), `release_remaining_buy_reservation` (idempotent by event marker).
- `apply_external_fills` now releases the settled portion per BUY fill inside the same atomic per-fill transaction, and sweeps the residual via `release_remaining_buy_reservation("fully-filled")` once locally-applied quantity reaches approved quantity.
- `_release_terminal_buy_reservation` now only fires for CANCELLED/REJECTED/EXPIRED (never FILLED) and releases only the remainder.
- `cancel_external_paper_order` now calls `apply_external_fills` to sweep any last-moment fills before releasing the remainder (previously skipped fill sweep entirely on cancel).
- Tests added: broker-FILLED-with-no-fills retains reservation + critical FILL_QUANTITY_MISMATCH reconciliation, then delayed fills settle and release in full; partial-fill-then-cancel releases only remainder; repeated reconciliation does not over-release. 13/13 pass in test_external_paper_broker.py.

## Reconciliation
- Part 8: split reconciliation into `_reconcile_locked` (outer fail-safe: any unhandled exception persists a `RECONCILIATION_INTERNAL_ERROR` critical record via a bounded try/except before propagating; failure to even persist raises `RECONCILIATION_PERSIST_FAILED`) wrapping `_run_reconciliation` (all the actual stage logic). Added statuses FILL_APPLICATION_FAILED, MALFORMED_BROKER_ORDER, MALFORMED_BROKER_FILL, BROKER_STATE_UNKNOWN, RECONCILIATION_INTERNAL_ERROR, RESERVATION_MISMATCH, SHARE_RESERVATION_MISMATCH to `CRITICAL_RECONCILIATION_STATUSES`.
- Previously `apply_external_fills` was called unguarded inside reconciliation — any raised `ExternalPaperError` (malformed fill shape/quantity/price/namespace) escaped reconciliation entirely with zero persisted evidence. Now wrapped: known fill errors -> MALFORMED_BROKER_FILL, anything else -> FILL_APPLICATION_FAILED (and reservation release is skipped via `else:` on failure, so cash/shares stay safely reserved). `_validate_order_response`/`_state_from_order` failures now map to precise MALFORMED_BROKER_ORDER/BROKER_STATE_UNKNOWN instead of generic UNKNOWN. Numeric-conversion errors in the broker positions/account comparison block map to RECONCILIATION_INTERNAL_ERROR instead of generic UNKNOWN.
- Added a defensive post-fill invariant check (remaining reservation must never go negative) that flags RESERVATION_MISMATCH/SHARE_RESERVATION_MISMATCH — belt-and-suspenders on top of the Part 2/3 clamping.
- Tests: malformed fill quantity persists MALFORMED_BROKER_FILL critical and blocks further submission; malformed broker order (quantity drift) persists MALFORMED_BROKER_ORDER; an unexpected exception inside fill application persists FILL_APPLICATION_FAILED; a non-numeric broker cash value persists RECONCILIATION_INTERNAL_ERROR. 25/25 in test_external_paper_broker.py.

## Timestamp validation

## Runtime secret isolation
- Part 11 root cause: `paper_runtime/configuration.py::_load_dotenv_if_present` called `find_dotenv(usecwd=True)`, which searches UPWARD from the process cwd. Since `cli.py::_build_runtime_client` spawns the runtime with `cwd=REPO_ROOT`, this silently discovered and loaded the *main repo's own* `.env` (Anthropic/Reddit/Robinhood/database secrets) into the isolated runtime's environment — defeating the isolation despite the subprocess env dict itself being minimal.
- Fix: removed the upward search entirely; `_load_dotenv_if_present` now loads a dotenv file ONLY if explicitly named via `PAPER_RUNTIME_ENV_FILE` (no scanning). Updated `cli.py::_paper_runtime_command_env` to allowlist-copy exactly `PATH, PYTHONPATH, ALPACA_API_KEY, ALPACA_API_SECRET, ALPACA_IS_PAPER, ALPACA_BASE_URL, PAPER_BROKER_PROVIDER, PAPER_RUNTIME_ENV_FILE` from the main process's environment (verbatim pass-through, never parsed/used by the main process) — every other secret (Anthropic/Reddit/Robinhood/database/market-data) is excluded by construction since it's an allowlist, not a copy.
- Updated `.env.example` to document the pass-through vs. dedicated-file mechanisms and added `PAPER_RUNTIME_ENV_FILE`.
- Tests: `paper_runtime/tests/test_configuration.py` (runtime ignores cwd/parent-dir `.env`, loads only the explicitly-named file, real env takes precedence, health output has no credential values) and `tests/unit/test_cli_runtime_env_isolation.py` (unrelated secrets never forwarded, allowlisted keys pass through verbatim, env contains only allowlisted keys). 1662 passed/15 skipped main suite; 46/46 paper_runtime.

## Broker numeric validation
- Part 13: replaced 4 truncating conversions with strict finite+integral Decimal checks — `external_broker.py::_payload` (`int(Decimal(intent["quantity"]))` -> `_exact_int`), `_validate_order_response`'s quantity/limit_price/filled_quantity (added `.is_finite()` + integral checks, previously NaN/Infinity could slip through untouched since `Decimal("NaN")`/`Decimal("Infinity")` parse successfully), `apply_external_fills`'s fill quantity/price (same), and `paper_runtime`'s `dispatcher.py::_validate_confirmed_long` + `lumibot_gateway.py::_order_to_snapshot` (`int(float(...))`/`int(Decimal(...))` -> new `models._parse_exact_int` helper, also hardened `_parse_decimal` to reject non-finite values globally).
- Tests: fractional/NaN/Infinity broker fill and order quantities all persist critical MALFORMED_BROKER_FILL/MALFORMED_BROKER_ORDER reconciliation; paper_runtime confirmed-long check rejects a fractional broker position quantity (MALFORMED_PAYLOAD). 41/41 in test_external_paper_broker.py; 47/47 in paper_runtime.

- Part 14 (frozen notional): `_intent()` previously validated the strictest-notional-cap against the STORED `notional_usd` field directly, never recomputing `quantity * limit_price` — a tampered/corrupted row with a low stored notional next to a high quantity/price would pass. Added `_validate_frozen_notional(intent, cfg, risk)`: recomputes and requires exact equality with stored `notional_usd`, cross-checks against the approved risk decision's `approved_notional_usd` when the BUY path approved via a risk decision, applies the strictest cap to the *recomputed* value, and fails closed with `FROZEN_INTENT_MISMATCH` (added to `CRITICAL_RECONCILIATION_STATUSES` along with `EXTERNAL_NOTIONAL_LIMIT`). Called from `_intent()` (covers preview/submit/retry) and again independently in `_run_reconciliation` (wrapped to persist a critical record rather than raise, consistent with Part 8). Test: hand-crafted corrupted row fails closed with "recomputed notional" error. 42/42 in test_external_paper_broker.py.

- Part 15 (transaction ordering): audited — already satisfied. Every reservation/event-append call in the submit/retry/cancel paths uses the repo layer's default `commit=True` (auto-commits immediately after its own single statement), so no transaction is ever held open across a `runtime.*` call; the only explicit `BEGIN IMMEDIATE`/`commit=False` usage is `apply_external_fills`'s per-fill block, which runs entirely after the runtime response is already in hand (no runtime call inside it). No code change was needed; added regression tests that instrument a fake runtime to assert `conn.in_transaction is False` at every runtime call across a full preview->submit->fill->reconcile flow and a submit->cancel flow — both pass, empirically confirming the invariant end-to-end.

- Part 16 (queue-state lifecycle): `paper_external_submission_queue` rows were inserted once with hardcoded `AWAITING_OPERATOR_EXTERNAL_SUBMISSION` and NEVER updated afterward — no code anywhere read or derived a live status, so the queue would silently stay "awaiting submission" forever regardless of what actually happened. Added `derive_external_queue_status`/`list_external_submission_queue_view` in external_broker.py: status is always computed fresh from the latest external order event for that intent (never a separately-maintained column that can drift), with `BLOCKED_BY_RECONCILIATION` surfaced for a non-terminal order under an active critical reconciliation, and terminal states (FILLED/CANCELLED/REJECTED/EXPIRED) always shown as-is. Added read-only `repo.list_external_submission_queue`, CLI command `external-paper-queue-show` (DB-only, no runtime client/credentials needed) and `external_paper_queue_show_cli`.
- Tests: queue moves off AWAITING_OPERATOR_EXTERNAL_SUBMISSION once submitted (previously would have stayed stuck); non-terminal order under critical reconciliation shows BLOCKED_BY_RECONCILIATION; fully-filled order shows the immutable terminal FILLED status. 47/47 in test_external_paper_broker.py.

- Part 17 (CLI error safety): `_external_paper_cli`'s generic `except Exception` branch returned `str(exc)` verbatim as the error message — could leak filesystem paths/subprocess detail for an unexpected failure. Added `_sanitized_cli_error`/`_bounded_message`: `ExternalPaperError` and `RuntimeOperationError` (both already curated, bounded domain errors) pass through their own code/message; any other `RuntimeClientError` (unavailable/timeout/protocol-violation) maps to a fixed generic "runtime unavailable" message; anything else collapses to `EXTERNAL_RUNTIME_ERROR` / "an unexpected internal error occurred" — never the exception's own text. Applied to `_external_paper_cli`, `external_paper_order_show_cli` (previously had no generic-exception catch-all at all), and the new `external_paper_queue_show_cli`. CLI main() already returns a nonzero exit (2) whenever any command's outcome contains an "error" key, and `RuntimeClient.diagnostics()` already exposed only a bounded suppressed-line count (no change needed there).
- Tests: unexpected exception text never appears in the sanitized output; domain errors still pass through their real code/message; oversized messages truncate. 6/6 in new test_cli_error_sanitization.py.
